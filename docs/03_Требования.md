# Требования

**Проект:** Учёт заявок на ремонт телефонов. **Заказчик:** MyСмарт. **Автор:** Кузнецов Иван Евгеньевич, 12ТЭС.
**Версия документа:** 1.0. **Дата:** 19.11.2026.

## Бизнес-требования

- **BR-1:** сократить потери времени и исключить утерю сведений при приёме, поиске и выдаче телефонов в сервисном центре «MyСмарт».
- **BR-2:** обеспечить приёмщику и мастеру быстрый доступ к актуальному списку заявок и текущему этапу ремонта каждого устройства.
- **Показатель результата:** время поиска заявки по номеру или модели телефона на списке из 10 записей сокращается с 1–2 минут (по бумажному журналу) до 5 секунд или быстрее.

## Функциональные требования

- **FR-1:** система позволяет создать заявку с автоматическим уникальным номером, моделью телефона, описанием поломки и начальным статусом «Принят».
- **FR-2:** система отображает общий список всех заявок и при выборе строки подставляет её данные в поля формы для просмотра и редактирования.
- **FR-3:** система выполняет поиск заявки по номеру или части названия модели телефона, а также фильтрует список по выбранному статусу («Все», «Принят», «В ремонте», «Готов», «Выдан»).
- **FR-4:** система позволяет переводить статус выбранной заявки строго по цепочке: **«Принят» → «В ремонте» → «Готов» → «Выдан»**; перескок через этапы или возврат назад запрещены.
- **FR-5:** система позволяет отредактировать модель телефона и описание поломки у выбранной заявки с проверкой заполнения обязательных полей.
- **FR-6:** система удаляет выбранную заявку только после подтверждения действия пользователем в диалоговом окне.
- **FR-7:** система в реальном времени отображает количество заявок по каждому статусу и общее число заявок в нижней панели окна.

## Нефункциональные требования и ограничения

- **NFR-1:** список из 10 демонстрационных записей открывается, фильтруется и обновляется не более чем за 2 секунды на стандартном офисном ПК под управлением Windows 10/11 (процессор от 2 ГГц, ОЗУ от 4 ГБ).
- **NFR-2:** попытка сохранить или изменить заявку с пустыми обязательными полями («Модель телефона» или «Описание поломки») или выполнить действие без выбора заявки вызывает понятное диалоговое предупреждение; некорректная запись не сохраняется.
- **NFR-3:** приложение работает на ОС Windows (а также других ОС с Python 3.11+ и Tkinter), имеет читаемый интерфейс без наложения элементов; работоспособность подтверждается ручными проверками в `tests/manual_checks.md`.
- **Ограничения:** срок разработки — 3 спринта по 2 недели (6 недель); один разработчик; стек — Python + Tkinter без сторонних библиотек; хранение данных — список словарей Python в оперативной памяти без СУБД; сохранение данных после закрытия программы не входит в первую версию; используются только вымышленные демонстрационные данные.
- **Дополнительно по желанию:** сохранение и загрузка заявок из локального JSON-файла (вынесено в будущие улучшения).
- **Приоритеты:** обязательные (Must Have) — `FR-1`, `FR-2`, `FR-3`, `FR-4`, `FR-5`, `FR-6`, `NFR-1`, `NFR-2`, `NFR-3`; желательные (Should Have) — `FR-7`.
