# Техническое задание

**Проект:** Учёт заявок на ремонт телефонов. **Заказчик:** MyСмарт. **Автор:** Кузнецов Иван Евгеньевич, 12ТЭС.
**Версия документа:** 1.0. **Дата:** 19.11.2026.

## Назначение и функции

Система предназначена для автоматизации учёта заявок на ремонт мобильных телефонов сотрудниками сервисного центра «MyСмарт». Основание — документ [Требования](03_Требования.md).

Обязательные функции:
- **FR-1:** добавление новой заявки с автонумерацией и статусом «Принят».
- **FR-2:** вывод списка заявок в таблицу и отображение выбранной записи в полях карточки.
- **FR-3:** поиск по номеру или модели телефона и фильтрация списка по статусу.
- **FR-4:** последовательный перевод статуса по цепочке «Принят» → «В ремонте» → «Готов» → «Выдан».
- **FR-5:** редактирование модели телефона и описания поломки с проверкой обязательных полей.
- **FR-6:** удаление выбранной заявки с подтверждением.
- **FR-7:** подсчёт и отображение статистики заявок по статусам.

## Интерфейс

- **Главное окно:** одно окно Tkinter (`900x560` пикселей, с возможностью изменения размера), разделённое на четыре логические области:
  1. **Панель поиска и фильтрации (верх):** поле поиска по номеру/модели, выпадающий список фильтра по статусу («Все», «Принят», «В ремонте», «Готов», «Выдан»), кнопки «Найти» и «Сбросить».
  2. **Таблица заявок (центр):** компонент `ttk.Treeview` со столбцами `№ заявки`, `Модель телефона`, `Описание поломки`, `Статус`.
  3. **Карточка заявки и действия (низ):** поля ввода «Модель телефона» и «Описание поломки», информационная метка текущего номера и статуса выбранной заявки, кнопки «Добавить заявку», «Сохранить изменения», «Следующий статус», «Удалить заявку», «Очистить форму».
  4. **Строка состояния / статистика (подвал):** счётчики заявок («Всего», «Принят», «В ремонте», «Готов», «Выдан»).
- **Обработка ошибок:** при пустых обязательных полях, попытке изменить статус уже выданной заявки («Выдан») или нажатии кнопок редактирования/удаления без выбранной строки появляется окно `messagebox.showwarning` с понятным текстом.
- **Макеты:** текстовая схема интерфейса описана выше; актуальные скриншоты работающего окна размещаются в `docs/images/` и в [Документации продукта](07_Документация_продукта.md).

## Данные и реализация

- **Стек:** Python 3.11+ и стандартный модуль `tkinter` (`ttk`, `messagebox`). Внешние библиотеки не требуются.
- **Структура записи (словарь Python):**
  - `id` (`int`) — уникальный номер заявки, генерируется автоматически (`1, 2, 3...`), обязательное, только для чтения;
  - `model` (`str`) — модель телефона (например, `"iPhone 13"`), обязательное, непустая строка;
  - `issue` (`str`) — описание поломки (например, `"Разбит дисплей"`), обязательное, непустая строка;
  - `status` (`str`) — текущий статус ремонта, обязательное, одно из значений: `"Принят"`, `"В ремонте"`, `"Готов"`, `"Выдан"`.
- **Хранение:** список словарей `orders: list[dict]` в оперативной памяти. При запуске программы список пуст; при закрытии окна данные очищаются.
- **Правила целостности:**
  - пробелы по краям вводимых строк обрезаются (`.strip()`); пустые строки не допускаются;
  - при создании новой заявки всегда устанавливается статус `"Принят"`;
  - переход статуса возможен только на один шаг вперёд по списку `["Принят", "В ремонте", "Готов", "Выдан"]`.
