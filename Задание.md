# Учебный проект: приложение для заказчика

Вы — разработчик компании «MySoft». Выберите заказчика My[название] и создайте за 3 спринта по 2 недели небольшое приложение, которое решает одну его проблему. Работайте индивидуально; тему согласуйте с преподавателем.

**На выбор:** заявки ремонтной мастерской; запись в груминг-салон; выдача настольных игр в клубе; бронирование репетиционных комнат; учёт расходников 3D-мастерской; регистрация на экскурсии. Можно предложить свою тему. Стартовый пример — мастерская «MyМастер».

## Что сделать

1. Заполнить README: заказчик, проблема, 5–6 функций, стек, запуск и план на 3 спринта.
2. Адаптировать семь шаблонов в docs/: заменить примеры и подсказки своими данными. Вести протоколы по факту встреч и отчёт по итогам каждого спринта.
3. Создать небольшую систему на Python + Tkinter: окно, поля ввода, кнопки, список записей, проверка ввода и поиск. Записи хранить в списке словарей Python только во время работы программы. База данных и SQL не требуются; после закрытия записи могут сбрасываться. Сохранение в JSON-файл — дополнительная задача по желанию.
4. В начале каждого спринта выбрать цель и задачи, в конце показать работающую версию и записать, что улучшить. Вести задачи в Issues и GitHub Projects; использовать main и ветки feature/..., объединять изменения через pull request. Делать содержательные коммиты по мере работы.
5. Вручную проверить основные сценарии и ошибки ввода, записать фактические результаты в `tests/manual_checks.md`. Автоматические тесты не обязательны. Добавить скриншоты и проверить запуск по инструкции на другом компьютере.
6. Подготовить выпуск v1.0: код, документацию, демонстрационные данные без реальных персональных сведений и краткие итоги. Согласовать условия использования кода и добавить LICENSE с выбранным текстом.

**Готовый результат:** другой человек понимает назначение проекта, запускает приложение по README и выполняет заявленные сценарии; в репозитории видны задачи, ход работы и результаты проверок.

**Углубление по согласованию:** расчёт критического пути, сравнение плана и факта стоимости, освоенный объём, дополнительные диаграммы и функции. В базовую версию не включать всё сразу.

## Как использовать набор

Создайте свой репозиторий кнопкой Use this template или скопируйте содержимое шаблона в корень уже выданного репозитория студента. Папки src/ и tests/ пока пустые; .gitkeep сохраняет их в Git. Код, сценарии ручных проверок и готовые результаты студент создаёт сам. Подсказки в квадратных скобках постепенно заменяются ответами.
